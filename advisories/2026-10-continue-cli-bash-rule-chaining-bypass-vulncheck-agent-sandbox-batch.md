## TL;DR
On 2026-10-12 VulnCheck published a further block of CVE records against agent tooling, and four of them concern products this corpus's readers run. **Continue CLI**, the terminal agent of the Continue IDE project, matches a static `Bash(prefix*)` allow rule against the whole command line, so a command chained after an allowed prefix with `;`, `&&` or `|` runs without the confirmation the dynamic evaluator would have asked for (**CVE-2026-109560**, CVSS 4.0 7.7). An older record, **CVE-2026-76072** (8.3, published 2026-08-24 and untracked here until today), says the destructive-command denylist that is the only barrier in headless and auto mode misses most of the filesystem and misparses a home-directory variable. Both GitHub issues (opened 2026-07-19 and 2026-09-17) are open with no maintainer reply, npm's latest `@continuedev/cli` is still 1.5.47 from 2026-06-18, and the vendor's security tab is empty. **sandboxed.sh**, the Rust backend behind the Orb desktop and iOS clients that run Claude Code, Codex, OpenCode and other agents on remote machines, attached shells to container workspaces with `nsenter` and without `--root`, so agent-run code resolved absolute paths on the host and could read and rewrite host files (**CVE-2026-109569**, 9.3); the fix commit makes the hardened behaviour an environment flag that is off by default. **Vercel deepsec**, the agent-powered vulnerability scanner, extracted result tarballs from its sandboxes with plain `tar`, so a prompt-injected agent in the sandbox could plant a symlink and write files on the orchestrator host (**CVE-2026-109375**, 4.9); fixed in 1.1.17 in May, record published now. **Network-AI**'s `ClaudeHookBridge`, a PreToolUse hook sold as an operator-facing hard gate for Claude Code, checked deny patterns against only the first candidate field of a tool call, so a payload in a `Write` body beside a benign path passed (**CVE-2026-109331**, 7.5; vendor 8.4), fixed 5.15.2 on 2026-09-27 as the second fix of the same control. If you run Continue CLI unattended on content you do not control, stop until a release carries a fix; everything else here is an upgrade or a flag.

## What happened

The GitHub Advisory Database's `agent` and `mcp` listings on 2026-10-13 showed unreviewed rows dated 2026-10-12 with no package metadata, the shape the [10-10 and 10-11 wave](2026-10-vulncheck-single-researcher-agent-mcp-gateway-cve-wave-mini-swe-agent-env-leak.md) had. The CNA is VulnCheck on every record below, the references are issues, permalinks and vendor advisories, and the scores are VulnCheck's unless stated. These four are the ones with an audience here; the same listings' EdgeEver, conductor-oss ([updated in its own file](2026-09-orkes-conductor-graalvm-workflow-rce-exploited.md)), FreeRDP and OTRS rows are out of scope.

Registry facts, checked 2026-10-13: `@continuedev/cli` latest is 1.5.47, published 2026-06-18, four releases in 2026; 4,038 downloads in the week of 2026-10-05. `continuedev/continue` has no published security advisories. Both affected ranges are "through 1.5.47," which is every version that exists.

The two findings compose. The first lets injected text run a command the operator never allowed in interactive use; the second says that in unattended use the allow list is already open and the denylist underneath it is partial. The reporter of the first argues the fix is to split compound commands and let the most restrictive verdict win; a community comment on each issue argues a string denylist cannot be made complete and the evaluator should resolve the command and validate arguments against tool schemas. Neither view has a maintainer response.

### sandboxed.sh (Orb): the fix is a flag, and the flag is off

CVE-2026-109569 (published 2026-10-12, CVSS 4.0 9.3, 3.1 8.8, CWE-1188): "code in container workspaces can access the host filesystem because `nsenter` attaches without `--root`. Agent-run code in a container workspace can resolve absolute paths on the host to read and modify host files, bypassing documented isolation." The record's `affected.vendor` is Th0rgal, the product sandboxed.sh, the range "through 1.3.0," and the repository `Th0rgal/orb`.

The referenced commit, "Harden deploy path: scoped nsenter root + versioned-symlink binary install," adds `SANDBOXED_SH_NSENTER_USE_TARGET_ROOT=1`, which appends `--root` to the `nsenter` arguments in `build_nsenter_command` so the attached shell sees only the container filesystem. The author's commit message says the change followed "a case where a mission escaped its container and rewrote host files," and that the flag stays off until each host has the agent binaries (Claude, Codex, OpenCode, MCP) inside the container, because with the host root hidden those binaries are no longer reachable. The commit page shows no date. The repository describes Orb as a desktop and iOS client for managing AI providers, machines and coding agents, with sandboxed.sh as its Rust backend; it runs Claude Code, Codex, Antigravity, OpenCode and Grok locally or on remote machines, "either on the configured host or in an isolated container workspace," and lists Hermes, ChatGPT, Grok Bot and Cursor Cloud as cloud agents. 530 stars.

Two things do not line up and are recorded rather than resolved. The releases page's newest tag is v0.12.0 (16 May, no year shown) and none of the ten releases shown mentions `nsenter`, `--root` or security, while the CNA range says "through 1.3.0"; the record's version source is not stated. And "fixed" here means a default-off environment variable, so a deployment that upgrades and does nothing else keeps the escape. There is no npm or PyPI package named sandboxed.sh; the product is installed from the repository. Status for this item: mitigated only where the operator sets the flag.

### Vercel deepsec: a May fix, a November-shaped record

CVE-2026-109375 (published 2026-10-12, CVSS 4.0 4.9, 3.1 6.1, CWE-59): `extractTarballLocally` in deepsec 0.1.0 before 1.1.17 "allows sandboxed code to write files outside the sandbox by planting links in result tarballs. Attackers controlling sandbox code, such as a prompt-injected coding agent, can plant symbolic or hard links in the host data directory to write arbitrary files on the orchestrator host." The record names 1.1.17 as unaffected.

deepsec is Vercel Labs' "security harness for finding vulnerabilities in your codebase powered by coding agents" (8.1k stars, npm `deepsec`, latest 2.3.10 on 2026-10-13). Its README describes fanning large scans out to Vercel Sandbox microVMs: the working tree goes up as a tarball, the agents run inside, and results come back as tarballs that the orchestrator extracts. The threat model the README states is that the sandbox is untrusted and the orchestrator host is not. The referenced pull request #46 (aydinnyunus, opened 2026-05-05, not merged as of 2026-10-13) proposed switching to `node-tar` and rejecting symlink and hard-link members; the maintainer's pull request #47 ("Improve windows compat and make tar usage more robust," merged 2026-05-05) added `tar@7.5.13` as a dependency with a commit titled "Support stricter tar," and the referenced commit `c5a4e42` is on `main`. The record's fixed version, 1.1.17, is from May; the CVE is from October. Anyone on 1.1.17 or later, which npm has served since then, is past it. Status for this item: patched.

### Network-AI: an incomplete fix to a Claude Code hard gate, fixed again

Network-AI is an npm package whose `network-ai hook pre-tool-use --deny ...` command installs a PreToolUse hook for Claude Code and is documented as an operator-facing hard security gate; deny patterns are checked first and in the default `observe` mode are the only hard block. Three CVE records on 2026-10-12 at 16:05 UTC point at three vendor advisories published 2026-09-27:

## Am I affected?

```bash
# Continue CLI: any installed version is affected by both records
npm ls -g @continuedev/cli 2>/dev/null; cn --version 2>/dev/null
# Where it runs unattended: look for headless / auto invocations in CI and cron
grep -rn --include='*.yml' --include='*.yaml' --include='*.sh' -E 'cn (-p|--headless|--auto)|continuedev/cli' . 2>/dev/null | head
# Permission rules with wildcard Bash prefixes (the chaining bypass needs one)
grep -rn 'Bash(' ~/.continue 2>/dev/null | head

# Orb / sandboxed.sh: is the hardened nsenter path on?
grep -rn 'SANDBOXED_SH_NSENTER_USE_TARGET_ROOT' /etc/systemd /etc/default ~/.config 2>/dev/null
# unset or anything but 1 means container workspaces see the host root

# deepsec: below 1.1.17 is affected
npm ls deepsec 2>/dev/null; npx deepsec --version 2>/dev/null

# Network-AI: below 5.15.2 has the hook bypass; check the installed hook too
npm ls -g network-ai 2>/dev/null
grep -n 'network-ai' ~/.claude/settings.json .claude/settings.json 2>/dev/null
```

## If you are affected

1. **Continue CLI, unattended use:** stop running it in headless or auto mode on repositories, pages or issues you do not control until a release names a fix for both issues. Where it must run, run it in a throwaway container with no credentials and no writable mount of anything you keep: [prevention/agent-sandboxing.md](../prevention/agent-sandboxing.md).
2. **Continue CLI, interactive use:** remove wildcard `Bash(prefix*)` allow rules. Every allowed prefix is a chaining point until the matcher splits compound commands.
3. **Orb / sandboxed.sh:** set `SANDBOXED_SH_NSENTER_USE_TARGET_ROOT=1` once the agent binaries are inside the container image, restart, and verify from inside a workspace that host paths no longer resolve. Treat any host where a mission ran on an untrusted task before that as touched: [playbooks/if-your-local-ai-agent-was-exploited.md](../playbooks/if-your-local-ai-agent-was-exploited.md).
4. **deepsec:** upgrade past 1.1.17 (current is 2.3.10) and check the orchestrator host's data directory for links the sandboxes did not create.
5. **Network-AI:** upgrade to 5.15.2 or later and re-read your deny rules against the new matcher; a rule that only names a `command` field never covered `Write` bodies.

## Prevention

- **A prefix allow list is not a parser.** Agent permission systems that approve by string prefix need to tokenize the command, apply the rule to every segment, and let the most restrictive verdict win. This is the third coding-agent tool in this corpus with a chaining or prefix bypass after [Claude Code's `find` confirmation bypass](2026-08-claude-code-desktop-ghsa-batch.md) and [Gemini CLI's headless workspace-trust RCE](2026-04-gemini-cli-trustissues-cve-2026-12537.md): [prevention/agent-sandboxing.md](../prevention/agent-sandboxing.md).
- **A denylist in unattended mode is a list of what the attacker may not say, not of what the attacker may not do.** Unattended runs need a container with no credentials and a read-only host, not a longer list.
- **Container isolation that leaves the host root mounted is not isolation.** For any agent runner that "attaches" to a container, check the mount and root namespace it attaches with, and prefer running the agent binary inside the image.
- **Result artefacts from a sandbox are untrusted input to the host.** Extract with a library that rejects links and absolute paths, into a directory the host does not execute from: [prevention/ci-cd-hardening.md](../prevention/ci-cd-hardening.md).
