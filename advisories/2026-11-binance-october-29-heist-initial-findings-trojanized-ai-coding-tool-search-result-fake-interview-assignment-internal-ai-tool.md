## TL;DR
Binance's initial findings (2026-11-03) on the 2026-10-29 theft of about 6.4 billion dollars describe a chain that started on developer workstations: in June 2026 a Wallet DevOps engineer searched for "a popular AI coding tool" and installed it through a tampered Homebrew installation; in September a second engineer, recruited through a job platform and two staged interviews, ran a downloaded "assignment" on a work computer that replaced a developer tool component and opened a channel to the attacker; on 2026-10-20 the attacker used that machine and "an internal AI tool" as a springboard to take control of two more engineers' accounts, found a deployment token on one of them, and on 2026-10-29 deployed a container and started unauthorized signing. The post does not name the AI coding tool, the search engine, the replaced component, or what the internal AI tool is; The Register names the component as pyenv. The FBI attributes the operation to TraderTraitor, a North Korean group. For this audience the lesson is the first two steps, which are the same lures that [the Rust-maintainer](2026-09-rust-maintainers-fake-interview-video-call-campaign.md), [Polinrider](2026-03-polinrider-multi-ecosystem-dprk-campaign.md) and [Joyfill](2026-07-joyfill-npm-devpopper-rat.md) files describe, now with an AI coding tool as the bait and an internal AI tool as the pivot.

## What happened

**The vendor's account.** Binance's post "29 October 2026 Binance Security Incident: Initial Findings and Response Update" (2026-11-03) calls the attack "a sophisticated, multi-stage campaign" and says "It was not a single isolated breach or a simple phishing incident." Its timeline: June 2026, Engineer A (Wallet DevOps) searched for a popular AI coding tool and installed it using a tampered copy of Homebrew; the security team detected the anomaly, replaced the device and rotated related credentials, but the post says Engineer A and colleagues on the wallet infrastructure team remained exposed to the attacker. September 2026, Engineer B was approached on a job-hunting platform by someone posing as a project director, interviewed over live video by a purported HR representative, then in a chat app by a purported CEO of a company that does not exist, and near the end asked to download an "assignment" to a work computer; it contained malicious code that endpoint protection did not detect at the time. 2026-10-20, the attacker used Engineer B's computer and an internal AI tool to gain control over Engineers A and C, and found a deployment permission token on Engineer A's computer. 2026-10-29 between 17:15 and 19:56, the attacker accessed Engineer C's computer, used credentials taken from Engineer A, deployed a container and launched the attack on wallet signing. Response: the affected wallet system and the internal AI tool were rebuilt with their access controls, devices replaced, the engineers' credentials and tokens decommissioned, all employee devices scanned, behavioural anomaly detection expanded, an independent review commissioned, and a security research fund planned. The post withholds some technical details "to avoid helping malicious actors" and says the investigation is ongoing.

**What the outlets add, attributed.** The Register (2026-11-03, Jessica Lyons) says the assignment repository ran during setup, replaced the pyenv component on the engineer's work computer, and established communication with an attacker-controlled server, and that Engineer A's token was a container deployment token; it does not name the AI coding tool. Its Homebrew link is a SANS ISC diary from 2026-05-01 about a search-ad campaign impersonating Homebrew's site to deliver a macOS stealer, which is background on the technique and not Binance's incident. SecurityWeek (2026-11-04, Eduard Kovacs) notes that "Binance's report does not explain how the AI tool was used, so the specific abuse method is unconfirmed", quotes Binance's "The 0-day malware was not detected by the endpoint security protection tools at the time", and cites Elliptic for laundering through about 12,000 wallets with no evidence of AI agents making decisions. The Hacker News (2026-11-03, Ravie Lakshmanan) quotes Chainalysis's Tom McLouth: "We've identified dozens of other job interview compromises that have led to wallet compromises", with more than 14.3 million dollars attributed to similar schemes over 18 months. The FBI attribution to TraderTraitor is reported by all three outlets and by The Register's 2026-11-02 article; North Korea rejected it through state media.

**What is unconfirmed.** Which AI coding tool was trojanized, whether the search result was an ad, which search engine, what "tampered copy of Homebrew" means (a fake Homebrew site serving a modified install command, as in the May ISC diary, or a modified formula), what the internal AI tool does and how it gave access to other engineers' machines, and whether the assignment's malware is related to the DevPopper, BeaverTail or OtterCookie families the corpus has filed under earlier fake-interview campaigns. Binance has not said. This file will be updated when the full report is published.

## Am I affected?

1. **Did you install an AI coding tool from a search result rather than the vendor's documented URL, especially on macOS through a pasted Homebrew or shell command?** Check your shell history for `curl ... | bash` and `brew install` lines you did not type from the vendor's page, and compare the installed binary's origin against the vendor's release.
2. **Did you run a recruiter's "assignment" repository on a machine that holds work credentials?** The sequence (job-platform contact, HR video screen, "CEO" chat interview, take-home repository that runs on setup) is the signature. Check `pyenv`, `nvm`, `node_modules/.bin` and similar tool directories for components that changed on the day you set the assignment up.
3. **What did that machine hold?** Deployment and container tokens, cloud credentials, SSH keys, password-manager sessions, and access to internal AI tools that can act on other people's accounts.

## If you are affected

- Treat the workstation as compromised: wipe and reinstall, do not clean. See [if you ran a malicious postinstall](../playbooks/if-you-ran-malicious-postinstall.md) for the credential inventory, then [rotating cloud credentials](../playbooks/rotating-cloud-credentials.md).
- Rotate every deployment, container-registry and cloud token that was on the machine, and revoke the machine's sessions in every internal tool, including AI assistants that hold delegated access.
- Tell your security team which recruiter, platform and repository were involved; the lure reuses infrastructure across targets.

## Prevention

- Install developer tools from the vendor's documented URL, verify the Homebrew formula or the release signature, and never paste an install command from a search result or an ad.
- Run take-home assignments in a disposable VM or a container with no credentials, or decline them. A real employer does not need you to run their repository on your work laptop.
- Keep deployment tokens off workstations: short-lived, issued by CI, scoped to one environment. See [credential hygiene](../prevention/credential-hygiene.md).
- An internal AI tool that can act on other engineers' machines or accounts is a lateral-movement path; scope it like a privileged service account and log what it does on whose behalf.
